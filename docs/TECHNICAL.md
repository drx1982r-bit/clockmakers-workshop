# Technical reference

Everything in this project is generated by Python. `project.blend` is a build artifact: running `scripts/build_scene.py` recreates it from scratch in about 6 seconds.

## Pipeline

```
make_audio.py   ──► audio/*.wav + events.json          (numpy synthesis, frame-synced)
build_scene.py  ──► project.blend                       (textures, materials, models, lights,
                                                         animation, cameras, grade, audio, Director)
render.py       ──► renders/frames/<preset>/*.png ──► renders/*.mp4   (resumable, with audio)
export_web.py   ──► web_viewer/data/{scene.glb, cameras.json, scene_data.js}
web_viewer/src  ──► web_viewer/viewer.js                (npm install && npm run build)
```

Developed and verified with Blender 5.2.3 LTS (the `bpy` module) on Python 3.13.

## Modules (`scripts/`)

| File | Contents |
|---|---|
| `cw_util.py` | bmesh primitives (lathe, extruded outlines, panels with holes, rings, gears with real tooth profiles, text-to-mesh), the `ShaderBuilder` node DSL, keyframe helpers for Blender 5 layered actions |
| `cw_materials.py` | about 60 procedural PBR materials, with no image textures needed |
| `cw_textures.py` | numpy-generated blueprint drawing (2048 × 1408), packed into the .blend |
| `cw_models.py` | room, windows and exterior, grand clock (case, dial, gear train, hands, pendulum, weights, bell, orrery), workbench and props, shelves, cabinet, wall clocks, haze volume, dust particles |
| `cw_lighting.py` | sun, sky fill, candle, pendant, orrery, bounce and accent lights, dusk world |
| `cw_animation.py` | the timeline, every animation, the 10 cameras, marker-based edit, audio strips |
| `cw_compositor.py` | the colour grade (bloom, lens dispersion, lift/gamma/gain, S-curve, vignette) |
| `cw_presets.py` | Low / Medium / High / Ultra for Cycles and EEVEE, plus GPU auto-detection |
| `director_addon.py` | the Director UI panel (embedded in the .blend as an auto-registering text block) |
| `render.py` | CLI renderer: stills, shot stills, resumable film frames, MP4 + AAC encode |
| `make_audio.py` | soundtrack synthesis |
| `export_web.py` | glTF + camera export for the browser version |

## Realism techniques

- **Materials.** Principled BSDF throughout:
  - Aged brass uses ambient-occlusion-driven tarnish in the crevices, brushed micro-scratches and anisotropy.
  - The clock hands are heat-blued steel made with real **thin-film interference** (330 nm oxide layer), just like real clock hands.
  - The walnut case has a French-polish clear coat.
  - The enamel dials have Voronoi crackle and a little subsurface scattering.
  - The candle wax uses subsurface scattering, the velvet uses sheen, and movement plates have a perlage (circular graining) finish.
- **Geometry.**
  - Hard-surface edges are bevelled with hardened normals.
  - "Smooth by angle" keeps flat faces crisp.
  - Repeated parts (chain links, knobs, ticks) share mesh data.
  - The scene has about 125,000 base polygons before bevels.
- **Gears.**
  - The clock train meshes correctly: each wheel's angle is `ratio × drive + phase`.
  - Ratios come from tooth counts, and phases are solved so teeth sit in gaps.
  - The escape wheel steps on each beat (2 beats per second), which drives the visible tick.
- **Light.**
  - A low warm sun with a 0.7° angular size gives crisp mullion shadows.
  - A principled-volume haze (anisotropy 0.62, noise-modulated density) produces god-rays.
  - Glass passes shadow rays (Light Path → *Is Shadow Ray*), so sunlight streams through the windows without slow caustics.
  - The light changes through the film: the sun dims and reddens, the pendant lamp flickers on, the orrery sun ignites and the candle flickers through fcurve noise.
- **Camera.**
  - Real full-frame focal lengths: 20, 32, 40, 50, 70, 85 and 100 mm.
  - 7-blade aperture bokeh, f/2 to f/5.6, and animated focus pulls.
  - Subtle hand-held drift (noise on the camera targets), 180° shutter motion blur, and a fade in and out.
- **Grade.**
  - AgX view transform, *Medium High Contrast* look.
  - Compositor: bloom, a hint of lens dispersion, cool shadows and warm highlights, a gentle S-curve and a vignette.

Every event time lives in `cw_animation.timeline_events()`. The audio generator and the browser version read the same values, so picture and sound stay frame-accurate.

## Audio

All sound is synthesised in numpy at 48 kHz:

- **Ticks:** filtered noise bursts through resonators plus wooden body modes.
- **Bell:** ten inharmonic bell partials (hum, prime, tierce, quint, nominal...) with slow beating.
- **Music box:** FM synthesis.
- **Pads:** additive detuned saws.
- **Reverb:** convolution with a synthetic impulse response.

The score is in D minor and resolves to D major (a Picardy third) when the clock strikes. Its music-box notes are locked to the clock's tick. You can replace `audio/music.wav` with your own track; keep the same name and rebuild, or swap the strip in Blender's Video Sequencer.

## Browser version

- three.js r180, bundled into one offline script.
- The scene and its animation are a glTF exported from Blender. The cameras are sampled every frame from the Blender cameras.
- Procedural Blender shaders cannot be exported, so the viewer rebuilds every material by name as a `MeshPhysicalMaterial`. Textures (wood, floorboards, plaster, rug, planets) are generated at load time on box-projected UVs. The blued steel uses iridescence, and glass uses transmission on High and Ultra.
- Volumetrics are approximated with additive light-shaft meshes, one per window pane, and dust points that light up only inside the sunbeams (traced back to the window openings in the vertex shader).
- Post-processing: bokeh depth of field (High/Ultra), Unreal bloom, AgX tone mapping, then a grade, vignette and film grain.

## Rebuilding

With Blender:

```
blender -b --factory-startup -P scripts/make_audio.py
blender -b --factory-startup -P scripts/build_scene.py
blender -b project.blend -P scripts/export_web.py
```

The browser bundle needs Node.js:

```
cd web_viewer/src && npm install && npm run build
```

## Known limitations and alternatives

- **No real-time game mode inside Blender.** Blender removed its game engine in 2.8. The Director panel plus EEVEE's rendered viewport provide interactive playback inside Blender, and the browser version is the fully interactive companion app.
- **Cycles on your PC is CPU-only.** Vega integrated graphics are not supported by Cycles (HIP needs RDNA or newer). EEVEE uses the integrated GPU instead.
- **Synthesised audio.** It is atmospheric and perfectly synced, but simpler than a recorded orchestral score. Swap in your own music if you like.
- **The browser version is real-time.** It cannot match Cycles' path-traced global illumination. It is designed for interactivity, not as a replacement for the rendered film.
